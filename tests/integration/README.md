# 같이 하기 통합 테스트

여러 방에 많은 사용자가 동시에 들어와 실제로 게임을 2라운드 진행하면서, 멀티플레이가 제대로 동작하는지 확인합니다.

## 실행

```bash
cd tests/integration
npm install
npx playwright install chromium   # 처음 한 번 (브라우저가 없을 때)
npm test
```

약 5~6분 걸리고, 끝나면 `PASS N FAIL N` 을 출력합니다. 실패가 있으면 종료 코드 1.
결과 상세는 `results.json`, 스크린샷은 `shot-*.png` 에 남습니다.

필요한 것: Node.js 18 이상, Python 3, 사용 가능한 포트 9100(중계 서버)·9200(사이트).

## 구성

| 파일 | 역할 |
|---|---|
| `build-test-copy.py` | 저장소의 `index.html` 로 테스트용 사본(`site/`)을 만듦. 게임 규칙은 그대로 두고 자동 플레이 봇·관찰용 훅만 덧붙이고, Supabase 대신 아래 가짜 서버를 쓰게 바꿈 |
| `relay.js` | Supabase Realtime 을 흉내 낸 로컬 중계 서버 (채널 · Presence · Broadcast). 사용자마다 30~120ms 지연, 창을 그냥 닫으면 `GHOST_MS` 동안 접속 정보가 남음(유령). 메시지 통계를 `relay-stats.json` 에 기록 |
| `fake-supabase-ws.js` | 게임이 쓰는 supabase-js Realtime API 만 구현한 클라이언트 (relay.js 에 WebSocket 으로 연결) |
| `server.js` | 사본 정적 파일 + 랭킹 REST(`scores`, `submit_score`) 흉내 |
| `run.js` | 시나리오와 확인 항목 |
| `run-all.js` | 위를 한 번에 실행 (`npm test`) |
| `tune-bot.js` | 봇 점프 타이밍 비교용 (server.js 를 켜 둔 상태에서 `node tune-bot.js 0.05,0.08,0.12 60000`) |

## 시나리오

- 브라우저 3개에 사용자 22명 + 방 목록만 보는 사람 2명
- 방 6개: 아이템전 4개(각 4명), 노템전 2개(각 3명). 절반은 방 목록에서 골라, 절반은 초대 링크로 입장
- 가득 찬 방에 5번째 사람 입장 시도
- 1라운드: 모든 방 동시 시작, 각자 자동 플레이 봇으로 약 140초 진행
  - 15초: 방 목록 '게임 중' 확인, 노템전 방에 게임 중 입장
  - 25초: 아이템전 방에서 달리는 한 명이 창을 그냥 닫음(유령)
- 라운드 사이: 유령이 남은 방의 시작 가능 여부, 방장 나가기 → 방장 넘김
- 2라운드: 모든 방 다시 시작
- 끝: 유령이 시간이 지나 방에서 빠지는지

## 확인 항목

방 목록(제목·방장·모드·인원·게임 중), 가득 찬 방 거절, 참가자 목록 일치, 라운드·방마다 점수 동기화·최종 순위·다른 방과 간섭 없음·아이템전 공격·노템전 아이템 없음·랭킹 자동 등록, 중간 입장, 유령 처리, 방장 넘김, 자바스크립트 오류, 프레임(fps), 메시지량.

## 한계

실제 Supabase 서버가 아니라 같은 방식으로 동작하는 로컬 중계 서버를 씁니다. 실제 서버의 동시 접속·메시지 한도, 실제 네트워크 끊김은 반영되지 않습니다.
